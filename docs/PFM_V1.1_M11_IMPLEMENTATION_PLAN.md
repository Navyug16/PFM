## 1. M11 Objective

The objective of Milestone 11 (M11) is to overhaul the **Overview Dashboard** and **Graph Visualizations** in PFM V1.1 so that any user — whether starting fresh mid-month or managing years of historical transactions — can **understand their complete financial position within a few seconds**.

### Key Deliverables & Focus Areas:
1. **Dashboard Hierarchy Redesign**: Reorganize `OverviewPage.tsx` into a clean, scannable, visual hierarchy with clear primary, secondary, and supporting cards.
2. **Available Funds & Starting Balance Semantics**: Prominently position **Total Available Funds** as the primary hero metric, eliminating user panic caused by negative period net cash flows during mid-month onboarding.
3. **Income vs Expenses Trend Redesign**: Redesign `CashFlowTrend.tsx` using the V1.1 Black/Dark + Orange design system so that earning vs spending, net cash flow trends, and financial trajectory are instantly recognizable on desktop and mobile.
4. **Graph Inventory & Simplification**: Audit all graphs across Overview and Insights to simplify presentation, ensure single-currency safety, eliminate visual clutter, and establish mobile-native visual layouts (375px/390px/430px).
5. **Component Modularization**: Refactor the monolithic `OverviewPage.tsx` (~896 lines of JSX) into clean, reusable dashboard sub-components in `src/features/overview/components/`.

## 3. Current Financial Metric Mapping

All financial metrics rendered on the dashboard and in graphs map directly to the centralized financial engine [`src/features/financial/utils/calculations.ts`](file:///e:/PFM/src/features/financial/utils/calculations.ts):

| Dashboard Metric | Calculation Function in `calculations.ts` | Underlying Data Sources | Multi-Currency Handling |
|---|---|---|---|
| **Available Funds** | `calculateAvailableBalanceMulti(accounts, transactions)` | Active accounts with `account_type` in `['checking', 'savings', 'cash']` + ledger history. | Returns map `{ [currency]: amount }`. Renders primary profile currency. |
| **Net Financial Position** | `getSingleCurrencyNetPositionMulti(accounts, transactions)` | All active accounts including credit cards, investments, and liabilities. | Returns map `{ [currency]: amount }`. |
| **Period Income** | `calculatePeriodIncomeMulti(transactions, accounts, start, end)` | `public.transactions` where `transaction_type === 'income'` within date bounds. | Excludes transfer transactions. |
| **Period Expenses** | `calculatePeriodExpensesMulti(transactions, accounts, start, end)` | `public.transactions` where `transaction_type === 'expense'` within date bounds. | Excludes transfer transactions. |
| **Period Net Cash Flow** | `calculatePeriodSavingsMulti(transactions, accounts, start, end)` | `Period Income - Period Expenses` calculated using integer cents (`sumCents`). | Preserves single-currency precision. |
| **Savings Rate** | `calculateSavingsRateMulti(periodIncome, periodExpenses)` | `((Income - Expenses) / Income) * 100`. Returns 0.00% if Income <= 0. | Prevents division-by-zero errors. |
| **Today Spending** | `calculateTodaySpendingMulti(transactions, accounts, todayStr)` | Expense transactions logged on current date `YYYY-MM-DD`. | Filtered to primary currency. |
| **Average Daily Spending** | `calculateAverageDailySpendingMulti(txs, accs, start, end, today)` | Total expenses in range divided by elapsed days (`Math.max(elapsedDays, 1)`). | Accurate for mid-month ranges. |
| **Category Share** | `calculateCategorySpending` + `calculateCategoryShare` | Sum of expenses per category UUID divided by total period expenses. | Sorted descending by amount. |
| **Cash Flow Intervals** | `groupCashFlowByInterval(transactions, period, start, end)` | Aggregates income and expenses into daily, weekly, or monthly buckets. | Filtered to primary currency for charts. |

## 4. Available Funds / Starting Balance Solution

### The Mid-Month Onboarding Problem:
When a new user registers on PFM on September 15th:
- Account Opening Balance = **₹50,000** (stored in `public.accounts.opening_balance`).
- September Income Logged = **₹0**.
- September Expenses Logged = **₹30,000**.
- **Calculated Period Net** = **-₹30,000** (`0 - 30,000`).
- **Calculated Available Funds** = **₹20,000** (`50,000 - 30,000`).

If the dashboard visually emphasizes a red **"-₹30,000 Deficit"** without contextual explanation, the user mistakenly believes PFM reports they are in financial trouble, when in fact they possess **₹20,000 of liquid cash**.

### The M11 Solution (Zero Math Modifications):
1. **Financial Rule Enforcement**:
   - Do **NOT** convert account opening balances into fake income transactions.
   - Do **NOT** modify `calculatePeriodIncome` or `calculatePeriodSavings`.
   - Preserve exact accounting definitions: Opening Balance = Capital Asset, Income = Earned Revenue.
2. **Dashboard UX Distinction**:
   - **Primary Solvency Metric**: **Available Funds** is displayed as the prominent Hero element with an explicit subtitle: *"Liquid cash available across checking and savings accounts"*.
   - **Integrated Cash Flow Strip**: Income (+), Expenses (-), and Net Cash Flow (+/-) are grouped underneath as **Period Cash Flow**, not as overall wealth indicators.
   - **Semantic Micro-Copy / Tooltip**: Next to Period Net, display an informative helper icon or tooltip:
     > *"Period Net reflects cash flow logged between [Start Date] and [End Date]. Your overall solvency is reflected in Available Funds (₹20,000)."*
   - **Non-Alarmist Neutral Styling for Mid-Month Deficits**: When Period Net is negative during a period with zero income, render the net figure with clear contextual labels rather than critical system errors.

## 8. Income vs Expenses Trend Redesign

The **Income vs Expenses Trend** (`CashFlowTrend.tsx`) is the highest-priority graph in M11.

### Key Questions Answered At a Glance:
1. *How much did I earn?* -> Clear Income bar + currency value.
2. *How much did I spend?* -> Clear Expense bar + currency value.
3. *Am I spending more than I earn?* -> Net Surplus/Deficit badge per interval (`+₹15,000 Surplus` or `-₹5,000 Deficit`).
4. *Is my situation improving or worsening?* -> Visual trajectory of net cash flow over sequential intervals.
5. *Which period had the biggest difference?* -> Highlight badge on max surplus / max deficit interval.

### Visual Design Specifications:
- **Design System Alignment**: Black/Dark Neutral surface (`bg-surface-primary` / `bg-surface-secondary`) + Neutral borders (`border-border-neutral`).
- **Color Rules**:
  - Income Bar = Positive Green tint (`bg-state-positive/20 border-state-positive/40` or `#22c55e`).
  - Expense Bar = Expense Red/Rose tint (`bg-state-expense/20 border-state-expense/40` or `#ef4444`).
  - Net Highlight / Accent = Brand Orange (`#f97316`).
  - **Forbidden**: AI black→orange gradient is strictly prohibited on normal financial charts.
- **Layout**:
  - **Desktop**: Horizontal paired bar layout with interval label on left, dual bars in middle, and tabular net callout on right.
  - **Mobile (375px/390px/430px)**: Stacked interval cards with dual progress bars, eliminating horizontal scroll clipping.

## 11. Empty / Low-Data States

Graphs and dashboard cards must handle sparse ledger data gracefully without breaking or rendering misleading charts:

1. **No Accounts Configured**:
   - Render `OverviewEmptyState type="no_accounts"`.
   - Primary CTA button: *"Add your first account"*.
2. **No Transactions Logged**:
   - Render `OverviewEmptyState type="no_transactions"`.
   - Primary CTA button: *"Log Income or Expense"*.
3. **Single Transaction / Low Data (<2 Trend Points)**:
   - `CashFlowTrend.tsx` renders a clean **Period Outlays Summary Card** showing total income, total expenses, net savings, and savings rate in text cards instead of a single 1-bar chart.
4. **Zero Income / Zero Expense in Range**:
   - Bar chart renders 0px height/width with `₹0` label, preventing `NaN%` or division-by-zero errors.

## 12. Mobile UX (375px, 390px, 430px)

The dashboard layout is engineered for seamless mobile responsiveness across key iPhone and Android viewports:

1. **Single-Column Grid Stacking**:

   - Fixed at `bottom-6 right-6 z-40` on mobile viewports (`md:hidden`).

## 13. Accessibility

All proposed dashboard and graph components enforce strict accessibility standards:

- **Color Contrast**: All primary text (`#f8fafc` dark / `#0f172a` light) satisfies WCAG AA contrast ratio of >= 4.5:1 against surface backgrounds.
- **Non-Color Indicators**: Financial trends use explicit icons (`ArrowUpRight`, `ArrowDownRight`, `Plus`, `Minus`) and text badges ("Surplus", "Deficit", "Safe", "At Risk") in addition to colors.
- **Keyboard Focus**: Interactive elements (period select dropdown, action buttons, card links) support visible focus rings (`focus-visible:ring-2 focus-visible:ring-brand-orange`).
- **Screen Reader Semantics**: Header elements use proper tag hierarchy (`<h1>`, `<h2>`, `<h3>`), and charts include descriptive `aria-label` attributes (e.g., `aria-label="Income vs Expenses trend chart for September 2026"`).

## 14. Performance

1. **Data Fetching Memoization**:
   - `useOverviewData.ts` fetches raw accounts, transactions, goals, and categories in a single `Promise.all` request.
   - Memoizes derived lookups (`categoryContext`, `accountContext`, `duplicateWarnings`, `qualityWarnings`) using `React.useMemo`.
2. **In-Memory Metric Calculation**:
   - Financial aggregations operate in-memory over transaction arrays using pure integer-cent operations in `calculations.ts` (< 5ms for 1,000 transactions).
3. **Component Re-render Optimization**:
   - Sub-components in `src/features/overview/components/` receive primitive or memoized props, preventing unnecessary re-renders when toggling modals or non-related state.
